# 开发与验证

## 运行测试

```sh
python3 -m unittest discover -s tests -v
python3 scripts/workflow.py doctor
```

已提供 [CI 模板](ci-template.yml)，可在 Windows、macOS 和 Linux 运行本地工具测试，不调用付费服务、不开摄像头、不下载大软件包。

自动测试尚未启用。维护者可将模板放入 `.github/workflows/tests.yml` 启用 GitHub Actions；提交该文件需要相应的仓库权限。

## 更新依赖

核对官方仓库 Release 的 tag、资产名、下载地址和 digest，更新 dependencies.json。不要把 latest 写成无约束自动升级，也不要从个人网盘或镜像替换官方源。升级后分别验证：下载/解压、软件启动、上游步骤兼容、导出/重导入、XR 加载和真人动捕。

不得把测试下载包、上游代码或用户输入加入 Git。审查 `git diff --cached` 和跟踪文件列表后再发布。新功能优先增加真实故障边界的测试，不给静态文案逐句写测试。

## 当前边界

- 工具负责下载解压和账本；Agent 负责平台安装细节、上游应用操作和结果判断。
- 状态文件原子写入但没有多写者锁，单项目必须串行操作。
- `ready` 是证据完整性门槛，不是计算机视觉评审器。报告内容和对应模型版本必须人工/Agent 核对。
- 不自动购买积分、不自动注册账户、不绕过系统权限；不收集密钥或会话数据。
