# 图片到可动角色

本说明是独立编写的编排和质量要求。Charakuru 的具体制作命令、部位格式和步骤从官方本地安装包读取。

## 输入与预算

保存原图并检查四肢、头顶/耳朵和脚是否完整。缺失部分先让用户确认补图，不擅自改造型。记录需要眨眼/张嘴的部位、是否有手指、耳朵/尾巴/头发/披风等摆动部位。优先一个角色跑通。

读取 Tripo 当前页面的费用与余额，说明本阶段预计消耗。获得用户预算范围后按该范围执行，不承诺固定总价。未登录/余额不足/余额未知均按 AGENTS.md 处理。

## 制作阶段

1. 按官方 Charakuru 当前版本创建项目与分部参考，确认形体和候选。头身比例必须适配该角色，不能把成人骨架直接压缩当作完成。
2. 保存每次生成任务的真实地址、状态、原始下载文件及对应部件。上游要求的分割、坐标恢复、UV、贴图和组装步骤按其文档执行。
3. 目视核对正面/侧面/背面：头身连接、耳根、手掌、脚、服装与配饰；先修复明显错误再绑定。
4. 绑定髋、脊柱、胸、颈、头、肩、臂、腕掌、腿与脚。无手指角色可不绑指骨，但不能省略腕掌。检查所有可变形顶点有有效且归一化的权重。
5. 对头发、长耳、尾巴等实际摆动部件建立独立骨骼、权重和适当碰撞；帽子等固定部件不强行摆动。通过运动/物理开关对比验证真实响应。
6. 根据设计制作可用的眨眼、张嘴等表情，并绑定 VRM 表达。静态五官贴图不能直接宣称具有表情；特殊固定眼睛设计记录“不适用”的原因。面部网格不足时需实际修复或说明限制。
7. 检查动作、材质、贴图与导出，进入 ACCEPTANCE.md。服饰与四肢穿插不能只改镜头遮住问题。

## 本地任务账本示例

以下仅演示命令结构，不代表当前项目真的提交过任务。

```sh
python3 scripts/workflow.py task projects/my-avatar head-geometry-01 intent --credits 100
# 在授权预算内执行真实提交后，立即替换为实际任务 URL 和实际积分数：
python3 scripts/workflow.py task projects/my-avatar head-geometry-01 submitted --url 'https://studio.tripo3d.ai/实际任务路径'
# 页面明确完成并下载核对后：
python3 scripts/workflow.py task projects/my-avatar head-geometry-01 completed
```

示例积分不是现行价格。账本键不能重复创建 intent，遇到重复须查看旧任务；失败任务不能自动以新键绕过防重复规则。确认失败/取消、确认不会重复扣费且用户预算允许后，才能建立关联的新尝试。

CLI 不操作 Tripo，也不执行付款；浏览器操作由 Agent 完成。网页变化时按当前可见页面判断，不依赖旧坐标。任务记录先于提交写入，之后异常可回查原任务。

## 保存与修复

保留原始生成文件、上一次可用版本和当前编辑源。每个角色独立项目；不将另一角色的关节坐标、头身比例、碰撞体位置原样套用。

任何几何、权重、表情、材质、物理或导出设置变化都需将受影响检查重新标记 pending，并用新导出文件复检。记录模型哈希，禁止拿旧版 XR 截图证明新版通过。
